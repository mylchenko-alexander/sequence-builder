# Sequence Builder v1.3.0.alpha

Браузерное frontend-приложение для создания, хранения и печати тренировочных последовательностей и документов на их основе. Ориентировано на карате, йогу, Tai Bo, боевые искусства и другие телесно ориентированные практики.

Приложение работает полностью локально и офлайн:

* без backend-сервера;
* без API;
* без авторизации;
* без аккаунтов;
* без permissions;
* без cloud;
* без синхронизации.

Все пользовательские данные хранятся локально в IndexedDB браузера.

В перспективе приложение может быть собрано как desktop-приложение через Electron или аналогичную технологию.

---

# СВОЙСТВА

Приложение предназначено прежде всего для тренеров и практикующих, которым необходимо:

* собирать тренировочные последовательности из собственной библиотеки изображений;
* хранить и структурировать тренировочные материалы локально;
* создавать собственные каталоги;
* добавлять описания, теги и свойства;
* создавать последовательности упражнений и техник;
* создавать документы на основе последовательностей;
* размещать несколько последовательностей внутри одного документа;
* печатать последовательности и документы через `Print → Save as PDF`.

---

# ОСНОВНЫЕ РАЗДЕЛЫ

В приложении три ключевых раздела:

1. **Каталог** - библиотека изображений поз, упражнений и техник.
2. **Последовательности** - создание и просмотр тренировочных последовательностей.
3. **Документы** - HTML/WYSIWYG-редактор с поддержкой текста, изображений и встроенных последовательностей.

---

# 1. КАТАЛОГ

Каталог предназначен для хранения изображений поз, упражнений, техник и других элементов тренировочного материала.

## Интерфейс

Каталог представляет собой визуальную библиотеку изображений.

Изображения отображаются в виде крупной сетки миниатюр, визуально близкой к Pinterest-подобной раскладке.

## Возможности

Пользователь может:

* создавать каталог;
* переименовывать каталог;
* удалять каталог;
* открывать каталог;
* добавлять изображения с локального диска;
* удалять изображения;
* просматривать изображения;
* открывать изображение в модальном окне;
* добавлять название;
* добавлять описание;
* добавлять теги и свойства.

Загруженное изображение **физически копируется** в IndexedDB. Приложение не должно зависеть от исходного файла на диске после загрузки.

## Дисциплинарные свойства

Набор тегов и свойств может отличаться для разных каталогов.

Например, каталог определённой дисциплины может использовать собственный набор характеристик.

Конкретная система расширенных характеристик не является обязательной частью базовой реализации MVP и должна оставаться расширяемой.

## Описание изображения

Для изображения можно добавить текстовое описание.

Редактор описания предполагается в формате Markdown/WYSIWYG.

# 2. ПОСЛЕДОВАТЕЛЬНОСТИ

Раздел предназначен для создания и просмотра тренировочных последовательностей.

## Интерфейс

Экран разделён на две рабочие области:

* список существующих последовательностей;
* Sequence Builder.

Sequence Builder является визуальной рабочей областью.

Изображения перетаскиваются из каталогов в последовательность через Drag & Drop.

```text
Catalog → Drag & Drop → Sequence Builder
```

Последовательность представляет собой упорядоченный набор элементов.

## Создание последовательности

Пользователь может:

* создать последовательность;
* задать название;
* добавить изображения из каталогов;
* удалить элементы;
* изменить порядок элементов;
* перемещать элементы Drag & Drop;
* редактировать параметры каждого элемента.

Одна последовательность может содержать изображения из разных каталогов.

## Sequence Item

`Sequence Item` - это конкретное использование изображения внутри последовательности.

Один и тот же `Image` может использоваться в разных последовательностях.

При этом `Sequence Item` хранит собственные параметры и не изменяет исходный объект в каталоге.

Примеры параметров:

* `imageId`;
* `order`;
* `repetitions`;
* `duration`;
* другие параметры, относящиеся именно к использованию изображения в sequence.

Таким образом:

```text
Catalog Image
      ↓
Sequence Item
      ↓
собственные параметры
```

Параметры изображения в каталоге и параметры его использования в последовательности независимы.

### Значение repetitions и duration

Смысл параметров может зависеть от дисциплины.

Например:

* карате/Tai Bo - количество повторений или длительность выполнения;
* йога - длительность позы или количество дыхательных циклов.

В MVP сами поля должны быть универсальными, без жёсткой привязки к одной дисциплине.

## Ограничение

**Sequence не может содержать другую Sequence.**

Sequences не комбинируются друг с другом как вложенные сущности.

Если необходимо расположить несколько sequences вместе, они размещаются внутри Documents.

---

## Generator

В последовательности присутствует генератор параметров.

Он работает на уровне всей последовательности и позволяет автоматически назначать случайные значения для элементов.

Например:

* случайное количество повторений;
* случайная длительность;
* другие параметры.

Набор параметров генератора должен быть расширяемым.

В MVP реализуется базовый генератор случайных значений для основных параметров.

---

## Sequence Explorer

Раздел просмотра созданных последовательностей.

Для каждой последовательности доступны:

* название;
* рейтинг;
* комментарий;
* набор тегов;
* дата создания;
* дата изменения;
* действия над последовательностью.

Пользователь может:

* открыть последовательность;
* удалить последовательность;
* изменить рейтинг;
* добавить комментарий;
* назначить несколько тегов;
* фильтровать последовательности по тегам;
* искать последовательность по названию.

### Rating

Каждая последовательность может иметь рейтинг от 1 до 5.

### Tags

Для последовательностей используется система тегов.

Пользователь может:

* создавать тег;
* переименовывать тег;
* удалять тег.

Для каждой последовательности можно назначить несколько тегов.

Один тег может использоваться в нескольких последовательностях.

# 3. ДОКУМЕНТЫ

Documents предназначен для создания полноценных тренировочных документов на основе текста, изображений и sequences.

## Интерфейс

Экран разделён на две рабочие области:

* дерево документов;
* HTML/WYSIWYG-редактор выбранного документа.

Дерево позволяет создавать более сложную иерархическую структуру документов.

Например:

```text
Training
├── Karate
│   ├── Warm-up
│   ├── Main
│   └── Cooldown
└── Yoga
    ├── Morning
    └── Evening
```

## Редактор

Пользователь может:

* создавать документы;
* задавать название;
* редактировать текст;
* форматировать текст;
* использовать заголовки;
* использовать жирный текст;
* использовать курсив;
* использовать подчёркивание;
* создавать списки;
* добавлять ссылки;
* добавлять изображения;
* вставлять sequences;
* удалять блоки;
* менять порядок блоков.

Документ автоматически сохраняется в IndexedDB.

## Вставка Sequence

Любая существующая sequence может быть вставлена в документ как полноценный отдельный блок.

Например:

```text
Текст

[ Sequence: Morning Karate ]

Текст

[ Sequence: Stretching ]

Текст
```

Встроенный Sequence Block отображает:

* название sequence;
* изображения в порядке sequence;
* параметры соответствующих Sequence Items.

### Несколько sequences

В одном документе можно разместить любое количество sequences и расположить их последовательно.

### Sequence внутри таблицы

Sequence может быть размещена внутри таблицы WYSIWYG-редактора.

Например:

```text
┌─────────────────┬─────────────────┐
│ Sequence A      │ Sequence B      │
│                 │                 │
│ img img img     │ img img img     │
└─────────────────┴─────────────────┘
```

Таким образом, Documents является механизмом композиции нескольких sequences в едином документе.

### Связь с Sequence

Встроенная sequence хранится как ссылка на `sequenceId`.

При открытии документа блок отображает актуальное состояние соответствующей sequence.

Если sequence была удалена, встроенный блок должен отображать корректное состояние ошибки или заглушку.

# ПЕЧАТЬ / PDF

Основной способ получения внешнего документа:

```text
Print → Save as PDF
```

Печати подлежат:

* отдельные sequences;
* документы.

## Печать Sequence

PDF должен отображать sequence в том же порядке, в котором находятся её элементы.

Для каждого элемента отображаются:

* изображение;
* соответствующие параметры.

## Печать Documents

Документ печатается как форматированный документ, содержащий:

* текст;
* изображения;
* встроенные sequences.

Sequences должны отображаться в печатной версии как полноценные блоки с изображениями и параметрами.

## Print Settings

Перед печатью пользователь может настроить:

* формат страницы - A4;
* Portrait;
* Landscape;
* размер изображений;
* количество элементов на странице;
* поля;
* масштабирование содержимого.

Изображения должны автоматически масштабироваться для корректного размещения на странице.

Основная цель - получение пригодного для печати тренировочного листа или документа.

# ХРАНЕНИЕ ДАННЫХ

Все данные приложения хранятся локально в IndexedDB.

IndexedDB является основным и единственным persistent-хранилищем пользовательских данных приложения.

Хранятся:

* каталоги;
* изображения;
* физические данные изображений;
* описания;
* свойства;
* теги;
* sequences;
* Sequence Items;
* рейтинги;
* комментарии;
* документы;
* содержимое документов;
* ссылки на встроенные sequences;
* настройки приложения.

После загрузки изображение физически копируется в IndexedDB.

Приложение не требует наличия исходного файла на диске.

# В БУДУЩЕМ

Следующие функции **не входят в текущий MVP**, но могут развиваться отдельно:

### Library of Ready Catalogs

Встроенная библиотека готовых пакетов каталогов:

* изображения;
* теги;
* свойства;
* описания;
* другая метаинформация.

Пользователь сможет установить выбранный пакет локально.

Функция не требует backend или cloud.

### Sequence Player / Rhythmic Timer

Режим воспроизведения уже созданной sequence:

* BPM;
* музыкальный размер;
* 2/4, 3/4, 4/4;
* опциональный звук;
* tick/beep;
* синхронизация Sequence Items с ритмом;
* использование `repetitions`;
* использование `duration`;
* использование дыхательных циклов.

Это инструмент проведения тренировки, а не автоматический тренер.
